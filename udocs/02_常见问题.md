# 常见问题：按实际报错处理

命令默认在 `python-cli/` 运行。Windows 使用 `py canctl.py`，Linux/macOS 使用 `python3 canctl.py`。第一步可运行 `canctl.py doctor`，保留完整输出；不要只截取最后一行。

## Python 能否不使用 sudo？

可以。Linux 管理员只需配置一次设备节点权限：

```bash
python3 canctl.py permissions
sudo python3 canctl.py permissions --apply
```

拔插设备后，普通用户执行 `python3 canctl.py doctor`，确认 `read/write=yes`。此后 `list`、`info`、`send`、`recv`、`test` 都不加 sudo。规则限于本项目两个 VID/PID，授予目标用户主组读写权限。只安装 Python 包不改变 USB 权限。

Windows 日常不需管理员，但每路 MI 接口需 WinUSB；macOS 安装 libusb 后按系统要求允许 USB 附件。Linux udev 和 rmmod 命令不适用于这两个系统。

## LIBUSB_ERROR_ACCESS [-3]

这是操作系统拒绝 USB 访问。Linux 按上节安装规则并重新插拔，使用普通用户 doctor 检查实际节点权限。若机器由管理员统一管理规则，让管理员检查是否有后续规则覆盖。不要使用 `chmod 777`、对所有 USB 放权或长期 sudo 运行 Python 来代替设备规则。

## LIBUSB_ERROR_BUSY [-6]

接口被内核驱动或其他程序占用。权限规则不能解除占用，sudo 也不能让两个程序共享同一路。

```bash
python3 canctl.py doctor
```

关闭其他 CAN 程序，按输出释放指定板卡。例如：

```bash
sudo python3 canctl.py release --interface vcan_usb --usb-path 1-1
python3 canctl.py --interface vcan_usb --channel 0 info
```

`1-1` 是示例，按实际输出替换；GS_CAN 将 `vcan_usb` 改为 `vkgs_usb`。解绑需要管理员权限，但释放后的日常收发不需要。重插可能重新绑定内核驱动；这是绑定状态变化，不是 udev 规则失效。若只看 UID/UUID，SocketCAN 的只读 sysfs 无需解绑。

## modprobe: Module vcan_usb not found，但 lsmod 能看到

测试脚本可以用 `insmod /tmp/.../vcan_usb.ko` 临时加载模块，并未把模块安装到当前内核的模块目录。`modprobe` 的磁盘查找结果与当前已加载模块不是同一回事。

优先按 doctor 输出选择性释放板卡。确实要卸载整个模块时，先退出使用它的程序，把**实际接口名**设为 down，再执行：

```bash
sudo ip link set can0 down
sudo ip link set can1 down
sudo rmmod vcan_usb
```

GS_CAN 使用 `sudo rmmod vkgs_usb`；若 doctor 显示系统 `gs_usb`，须按实际驱动判断，不能照抄 vcan_usb。上述 can0/can1 仅为示例。卸载会影响使用该模块的所有板卡。若提示 module in use，不要强制卸载，先查明占用。

## need two interfaces bound to vcan_usb; found 0

这是 SocketCAN 测试找不到目标驱动绑定的网络接口，不等于 USB 板卡不存在。尤其 `--no-build` 不编译也不加载驱动。关闭 Python，确认设备是 VCAN 且已接入当前 Linux（虚拟机需要 USB 直通）。回到仓库根目录：

```bash
sudo bash kernel/tests/vcan_usb/test_vcan_usb.sh --load-only
```

GS_CAN 模式将路径和脚本名中的 `vcan_usb` 改为 `vkgs_usb`。如果加载失败，保留脚本输出、诊断目录和 `dmesg`；不要直接重复 `--no-build`。两路绑定后才运行接线测试。编译依赖、gs_usb 冲突及 Secure Boot 排查见[驱动安装](08_Linux内核驱动安装.md)。

## Operation not supported: lib → lib64 / virtual environment not found

HGFS 等共享盘可能不支持 venv 的符号链接。无需反复在共享盘创建环境，也无需试图用 sudo 修复这种文件系统能力限制。在 `python-cli/` 用普通用户运行：

```bash
python3 canctl.py setup
python3 canctl.py doctor
```

新环境放在用户本地磁盘。若以前已有可执行但不完整的项目 `.venv-linux`，它会优先于新环境；可显式指定新解释器：

```bash
export VCANDRIVE_PYTHON="$HOME/.local/share/vcandrive/venv-linux/bin/python"
python3 canctl.py doctor
```

此设置仅对当前终端及其子进程生效。Windows 对应优先级是 `VCANDRIVE_PYTHON` → 项目 `.venv-win` → 本地用户环境；macOS 为项目 `.venv-mac`。无需把环境目录复制到另一种系统。

## receive timeout (0/60)

接收等待期间没收到帧。它与 ACCESS/BUSY 不同：先确认另一通道确实在发送、两端位率相同、CANH/CANL 对接、终端正确，且目标是另一条物理通道。按[快速入门](01_快速入门.md#5-接线并收发第一帧)只收发一帧，接收窗口先启动。完整测试会自己组织双向发送，不需要手工同时开两个接收命令。

## list 有两个通道，为什么 info 或测试仍失败？

list 只做发现。它不能证明打开权限、接口可独占、总线 ACK、数据内容或物理接线正确。doctor 也不会打开通道发送数据。info 成功证明相应控制查询成功；完整验收还需双路正确接线。

## command not found / 把两条命令粘成一条

`$py = ...` 是 PowerShell 语法，不能在 Linux Bash 执行。使用本版统一入口，无需这些变量。`./canctl --help./canctl --help`、`x sudo ...` 都不是有效示例；每次复制一个代码块中的完整命令，不包含提示符和额外字符。

## 多设备怎么确保没有打开错通道？

先 list 看当前连接，再用同一组 `--device` 或 USB 定位参数执行 info。保存完整 `uuid_hex` 和 `channel`，例如 `UUID:0`。端口链、bus/address、`canX`、枚举序号都不是永久硬件身份。插拔或换模式后重新发现和核对。软件 channel 与外壳标签的对应关系需要首次登记，详见[设备定位](09_SocketCAN使用手册.md#定位唯一板卡和通道)。
