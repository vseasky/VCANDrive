# 轻量设备管理窗口

窗口显示设备列表、当前模式、固件/硬件版本、UID 和各通道终端电阻状态；可以切换模式，也可以为选定通道设置终端电阻。界面使用 Python 标准库 Tkinter，无 Qt、浏览器、抓包或 OTA 页面。

Windows 用户可直接双击交付的 `USB_CAN_Device_Manager.exe`。需要设备对应的驱动；PCAN 模式依赖系统中可用的 PCANBasic.dll，VCAN 和 GS_CAN 模式按 [PythonCAN 使用手册](PythonCAN使用手册.md)配置 USB 驱动。

窗口启动后自动识别。单台设备自动选中，多台设备点击对应行；选择目标 VCAN、PCAN 或 GS_CAN，再点击“切换模式”。不需要选择当前后端。写入前重新核对当前打开句柄的身份；终端电阻按通道读取、设置并在同一连接中回读，切换模式后根据 UID 重新发现，并核对模式以及完整 40 字节身份信息。身份不符、设备占用或结果不确定时不自动重发写命令。

## 首次使用与故障排查

1. 用数据线连接设备，关闭正在占用它的抓包、收发或管理程序，然后运行单独交付的 `USB_CAN_Device_Manager.exe`。
2. 点“刷新设备”。预期至少有一行，能看到当前模式、固件版本、硬件版本和 UID；多台设备先核对 UID 再选中目标。
3. 在“终端电阻”区域选择通道。先查看“当前状态”，再选择目标“开”或“关”并点击“设置终端电阻”；状态会从设备回读核对。PCAN 模式使用实际枚举的 PCAN 通道句柄，列表只显示可识别的通道。总线两端各需一处 120 Ω 终端；已有外置终端时，不要再打开同一位置的内置终端。
4. 若要切换工作模式，在“目标模式”选 VCAN、PCAN 或 GS_CAN，点“切换模式”。设备会短暂断开并重新枚举；完成后再确认列表中的模式与 UID。新模式可能需要安装对应驱动。

终端状态显示“未知”时，该通道的读取未成功，先关闭占用程序再刷新；若设置结果不确定，刷新确认当前状态后再操作。切换模式后终端状态需重新读取，不要依据切换前的显示判断。

显示 0 台时，先检查 USB 数据线、供电和 Windows 是否已枚举设备；再确认当前模式所需驱动已经安装。PCAN 模式还要求系统能找到 `PCANBasic.dll`，且空闲通道未被其他 PCAN 程序占用。VCAN/GS_CAN 模式如果仍无法识别，先按[快速入门的 Windows 步骤](快速入门.md#2-windowspython-usb-路线)核对 `MI_xx` 驱动。状态栏若提示某接口被占用，关闭相应软件后刷新，不要在结果不确定时连续点击切换。

## 识别方式

VCAN/GS_CAN 读取现有 BSP_DEVICE_INFO，PCAN 使用 UCM1 握手及新增操作5读取相同字段：软件版本u32、硬件版本u32、UID[4]、UUID[4]，共40字节，小端。PCAN新查询的64字节响应为12字节信封、40字节信息、8字节保留零、末尾4字节CRC32；原32字节命令及终端配置、模式切换接口保持兼容。

PCAN 自动探测以只听模式打开空闲通道；占用中的通道不抢占，未返回有效管理协议和设备信息的设备不会列为可切换的自有设备。设备多通道按UID归并成一行。UID与CRC是设备识别/误操作检查，不是防伪或密码学认证。

PCAN 模式需要支持操作5的固件（本次样机版本0.0.0.48）；旧 PCAN 固件无法自动取得完整版本信息，需先更新。VCAN/GS_CAN仍使用原有接口。当前只有一台实机参加三模式测试，多设备列表及选择通过模拟测试验证，未宣称完成多台同时接入的实测。

硬件版本显示完整原始32位十六进制值，固件版本显示四段版本号。USB模式是软件人格，不代表更换实际硬件。
