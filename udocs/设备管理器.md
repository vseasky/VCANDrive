# 轻量设备管理窗口

只提供设备列表、当前模式、固件版本、硬件版本、UID 和模式切换。界面使用 Python 标准库 Tkinter，无 Qt、浏览器、抓包或 OTA 页面。

Windows 用户可直接双击交付的 `USB_CAN_Device_Manager.exe`。从源码运行时，先按 [PythonCAN 使用手册](PythonCAN使用手册.md)安装依赖，再在 `python-cli/` 目录执行：

```powershell
$py = '.\.venv-win\Scripts\python.exe'
& $py tools/device_manager_ui.py
```

也可用同一 Python 解释器打开 `tools/device_manager.pyw`，避免控制台窗口。源码运行需要 python-can、USB 后端依赖及相应驱动；Tkinter 随常规 Windows Python 安装提供。PCANBasic.dll 通常从系统加载，必要时指定 `--dll "完整路径/PCANBasic.dll"`。

窗口启动后自动识别。单台设备自动选中，多台设备点击对应行；选择目标 VCAN、PCAN 或 GS_CAN，再点击“切换模式”。不需要选择当前后端。写入前重新核对当前打开句柄的身份；切换后根据 UID 重新发现，并核对模式以及完整40字节身份信息。身份不符、设备占用或结果不确定时不自动重发写命令。

命令行仍可使用：

```powershell
& $py tools/device_manager.py list
& $py tools/device_manager.py switch pcan
& $py tools/device_manager.py switch vcan_usb --uid 设备UID
```

## 识别方式

VCAN/GS_CAN 读取现有 BSP_DEVICE_INFO，PCAN 使用 UCM1 握手及新增操作5读取相同字段：软件版本u32、硬件版本u32、UID[4]、UUID[4]，共40字节，小端。PCAN新查询的64字节响应为12字节信封、40字节信息、8字节保留零、末尾4字节CRC32；原32字节命令及终端配置、模式切换接口保持兼容。

PCAN 自动探测以只听模式打开空闲通道；占用中的通道不抢占，未返回有效管理协议和设备信息的设备不会列为可切换的自有设备。设备多通道按UID归并成一行。UID与CRC是设备识别/误操作检查，不是防伪或密码学认证。

PCAN 模式需要支持操作5的固件（本次样机版本0.0.0.48）；旧 PCAN 固件无法自动取得完整版本信息，需先更新。VCAN/GS_CAN仍使用原有接口。当前只有一台实机参加三模式测试，多设备列表及选择通过模拟测试验证，未宣称完成多台同时接入的实测。

硬件版本显示完整原始32位十六进制值，固件版本显示四段版本号。USB模式是软件人格，不代表更换实际硬件。
