# PCAN 模式设备管理接口

第一次识别和切换请先看[快速入门](快速入门.md)与[设备管理器](设备管理器.md)。PCAN 兼容模式下，普通 PCANBasic API 不负责切换本设备的工作模式。VCANDrive 设备通过保留的 CAN FD 管理帧提供只读设备信息、终端电阻配置和模式切换；[设备管理器](设备管理器.md)已经实现自动发现与身份核对。第三方 PCAN 设备不会被识别为本项目设备，也不应发送管理写命令。

## 使用现成工具

运行交付的 `USB_CAN_Device_Manager.exe` 查看多台设备的模式、固件版本、硬件版本、USB 速率、隔离类型、UID 和各通道终端电阻状态。选中设备后，每个 CAN 通道直接显示一个独立开关，点击即可设置并回读；也可以切换至 VCAN、PCAN 或 GS_CAN。若设备已经安装外部终端，先确认物理接线再设置。

PCAN 自动发现以只听模式打开空闲通道，读取管理握手、40 字节设备信息以及终端电阻状态。已被其他进程占用的通道不会被强制打开；旧固件如果不支持设备信息操作，也不会被当作可切换设备。写操作前重新核对 UID 与完整身份信息；终端设置在选中的通道上执行并回读，切换模式后按 UID 重新枚举并核对模式和版本。结果不确定时不自动重发。

## 管理帧协议

请求使用扩展 ID `0x1FFFFF00`，响应使用 `0x1FFFFF01`，均为 CAN FD 帧。请求固定 32 字节：`UCM1`（4 字节）、操作（1 字节）、参数（1 字节）、序号（LE16）、非零随机 nonce（LE32）、UID 原始 16 字节、CRC32/ISO-HDLC（LE32，覆盖前 28 字节）。UID 原始值由四个 32 位 UID 字各自按小端排列。操作 1 为握手，2 为设置模式，3 为读取终端，4 为设置终端，5 为读取设备信息，6 为读取当前 USB 速率。模式参数 0/1/2 分别代表 VCAN/PCAN/GS_CAN；终端参数 0/1 分别代表关/开；操作 6 的返回值 0/1/2 分别代表未知/FS/HS，参数必须为 0。旧版管理固件不支持操作 6 时，上位机应显示速率“未知”，不影响操作 1–5。

操作 5 的响应返回 40 字节信息：软件版本 u32、硬件版本 u32、UID[4]、UUID[4]，均为小端。管理帧只在设备自身 USB 路径处理，不在物理 CAN 总线上发出；扩展 ID `0x1FFFFF00` 和 `0x1FFFFF01` 应为本项目管理用途保留，应用不得用它们发送业务帧。此握手、nonce、UID、序号和 CRC 用于降低误操作风险，不构成身份认证或加密通道。

需要编写自定义 PCAN 上位机时，应按本页帧格式实现消息编码与应答校验，并先读取设备信息确认目标身份。切换模式会保存配置并重启 USB 设备，旧句柄立即失效；必须在重新枚举后验证目标设备身份。

原有 PCAN USB 命令兼容保留：`ERR_GEN1` 的 `bit_position` 为 0/2 时，分别切换到 VCAN/GS_CAN；`SET_ERR_GEN_S` 的 `bit_position` 为 0/1 时，分别关闭/开启所在通道的终端电阻。它们是历史映射，新上位机优先使用带身份核对与回读的管理帧。保留这些命令仅用于已有工具兼容，并不会改变标准 PCAN 帧格式或端点布局。
