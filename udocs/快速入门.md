# 第一次使用：从连接设备到收发第一帧

这页按新用户的操作顺序编写。先完成一条路线：Windows 上用 Python USB 后端，或 Linux 上用 SocketCAN。示例使用双通道设备、经典 CAN 500 kbit/s；成功后再尝试 CAN FD、DBC 或 CANopen。仓库可用 `git clone https://github.com/vseasky/VCANDrive.git` 获取，也可从 GitHub 下载 ZIP。下面的命令都从解压后的 `VCANDrive` 目录开始。

## 1. 接线并确认工作模式

在未连接生产总线的测试环境中，把设备 CAN0-H 接 CAN1-H、CAN0-L 接 CAN1-L。总线两端各接一个 120 Ω 终端；若使用设备内置终端，就不要在相同位置重复加外部终端。用可传数据的 USB 线连接电脑。只有一个节点或两通道未对接时，正常总线发送通常得不到 ACK；内部回环能测软件路径，但不能证明实际接线正常。

| 电脑与目标 | 本页路线 | 当前设备模式 |
|---|---|---|
| Windows，先验收或开发 Python 程序 | [Windows：Python USB](#2-windowspython-usb-路线) | VCAN 或 GS_CAN |
| Linux，使用 `candump`、`cansend`、C/C++ | [Linux：SocketCAN](#3-linuxsocketcan-路线) | VCAN 或 GS_CAN |
| 当前是 PCAN 兼容模式 | 先用交付的 [设备管理器](设备管理器.md)识别并切换 | 切换到所选路线的模式 |

Windows 上，运行单独交付的 `USB_CAN_Device_Manager.exe`，点“刷新设备”。列表应显示当前模式、固件版本、硬件版本、UID 和终端电阻状态。可选中通道设置内置终端，PCAN 模式也支持；如需切换，选中目标设备再选目标模式。切换会使设备重新枚举，旧窗口或程序句柄需要关闭后重新打开。此 EXE 不在源码仓库内，已有 VCAN/GS_CAN 模式的设备可直接继续下面的步骤。若显示 0 台，先按[设备管理器故障排查](设备管理器.md#首次使用与故障排查)处理。

Linux 上可用 `lsusb` 判断：`1d50:6080` 为 VCAN，`1d50:606f` 为 GS_CAN。PCAN 模式的 USB ID 和驱动不在这两条安装路线内。设备管理器适用于 Windows；不要根据外壳或 `can0` 名称猜模式。

## 2. Windows：Python USB 路线

在 PowerShell 中进入仓库的 `python-cli` 目录。先确认 `py -3 --version` 能显示 Python 3，再创建独立环境：

```powershell
cd .\python-cli
py -3 -m venv .venv-win
$py = '.\.venv-win\Scripts\python.exe'
```

根据第 1 步看到的模式，**只执行对应的一行**：

```powershell
& $py -m pip install -e .\vcan_usb   # VCAN
& $py -m pip install -e .\vkgs_usb   # GS_CAN
```

每个 CAN 通道是独立的 USB `MI_xx` 接口。若下方 `list` 看不到通道，检查 Windows 设备管理器里的 VID:PID 和 `MI_00`、`MI_01` 驱动。需要手工安装时，可使用 [Zadig 官方说明](https://github.com/pbatard/libwdi/wiki/Zadig)：在 `Options → List All Devices` 中逐个选中与设备 VID:PID 对应的 **MI_00/MI_01 子接口**，目标驱动选 `WinUSB`；不要选 USB 复合父设备，也不要选其他 USB 设备。PCAN 模式使用其兼容驱动，切换到 VCAN/GS_CAN 后才按这里检查 WinUSB。

设置后执行发现命令；把 `$backend` 改成与当前模式一致的值：

```powershell
$backend = 'vcan_usb'  # GS_CAN 改为 'vkgs_usb'
& $py .\tools\canctl.py --interface $backend list
```

**预期结果**：至少看到 `channel=0` 和 `channel=1`，以及相同的 `port_path`。下面的 0、1 是示例；若实际编号不同，用 `list` 显示的编号。收发测试要打开两个 PowerShell 窗口，都进入 `python-cli` 目录，并分别设置 `$py` 和 `$backend`。

先在窗口 A 启动接收：

```powershell
$py = '.\.venv-win\Scripts\python.exe'
$backend = 'vcan_usb'  # GS_CAN 改为 'vkgs_usb'
& $py .\tools\canctl.py --interface $backend --channel 1 --bitrate 500000 --termination on recv --count 1 --timeout 15
```

再在窗口 B 发送一帧：

```powershell
$py = '.\.venv-win\Scripts\python.exe'
$backend = 'vcan_usb'  # GS_CAN 改为 'vkgs_usb'
& $py .\tools\canctl.py --interface $backend --channel 0 --bitrate 500000 --termination on send 0x123 11223344
```

**预期结果**：发送端显示 `TX 1/1`，接收端显示 ID `123` 和数据 `11 22 33 44`。两端都必须使用相同位率。确认第一帧后，先运行每发送端每阶段 20 帧的**入门功能验收**；它检查经典 CAN、FD/BRS 与内部回环，但不包含全部压力和协议专项：

```powershell
& $py .\tests\hardware_test.py --interface $backend --channels 2 --mode bus --profile functional --frames 20 --window 1
```

没有接线时可先用 `--channels 1 --mode loopback --profile functional --frames 20 --skip-fd` 检查单通道内部路径；它不能代替双通道物理总线测试。完整参数见[Python 终端工具](Python终端工具.md)。更大帧数、混合帧矩阵、重复打开和 Linux 内核专项分别按[验收测试路线](验证路线.md)继续；写程序看[PythonCAN 使用手册](PythonCAN使用手册.md)与[Python API 参考](PythonAPI参考.md)。

## 3. Linux：SocketCAN 路线

在终端确认 USB ID，并安装构建工具（以下以 Ubuntu/Debian 为例）：

```bash
lsusb | grep -Ei '1d50:6080|1d50:606f'
sudo apt update
sudo apt install -y build-essential linux-headers-$(uname -r) iproute2 can-utils
```

进入**与当前模式对应的目录**并编译安装；这里以 VCAN 为例，GS_CAN 则将 `vcan_usb` 改为 `vkgs_usb`，并先按[驱动安装说明](Linux内核驱动安装.md#4-安装-vkgs-模块)处理系统 `gs_usb` 抢绑定：

```bash
cd kernel/vcan_usb
make
sudo make install
sudo depmod -a
sudo modprobe vcan_usb
ip -br link show type can
```

**预期结果**：出现两路 `canX` 接口。`can0/can1` 是 Linux 动态名称；若名称不同，后续命令按实际名称替换，并用[驱动安装说明](Linux内核驱动安装.md#5-确认每个-canx-的实际驱动)核对所绑定的模块。返回仓库根目录后，为两路设置相同位率与终端：

```bash
sudo ip link set can0 down
sudo ip link set can1 down
sudo ip link set can0 type can bitrate 500000
sudo ip link set can1 type can bitrate 500000
sudo ip link set can0 type can termination 120
sudo ip link set can1 type can termination 120
sudo ip link set can0 up
sudo ip link set can1 up
```

若接线两端已经各有外部 120 Ω 电阻，就把上面的 `termination 120` 改为 `termination 0`。在终端 A 执行 `candump can1`，再在终端 B 执行 `cansend can0 123#11223344`。**预期结果**：终端 A 显示 `can1  123   [4]  11 22 33 44`（空格格式可能略有差异）。按 `Ctrl+C` 结束监听。进一步验证 FD 和自动化脚本见[SocketCAN 使用手册](SocketCAN使用手册.md)。

## 4. 遇到问题先核对这些结果

| 现象 | 先检查 |
|---|---|
| 设备管理器显示 0 台 | USB 数据线、设备是否刚切换模式、PCANBasic.dll（PCAN 模式）、其他软件是否占用；见[设备管理器](设备管理器.md)。 |
| Windows `list` 无通道 | 模式与 `--interface` 是否一致、两路 `MI_xx` 是否为 WinUSB、是否仍被设备管理器或其他程序占用。 |
| `WinError 5` | 目标 `MI_xx` 已被另一个进程占用；关闭其他监听或管理软件后重试。 |
| Linux 没有 `canX` | `lsusb` 是否匹配、`modprobe` 是否成功、GS_CAN 是否被 `gs_usb` 抢绑定；见[驱动安装](Linux内核驱动安装.md)。 |
| 发送端显示成功但接收超时 | 两端位率、CAN_H/CAN_L、终端、是否两个独立节点及 `channel` 编号。只有一端在线时通常没有 ACK。 |
| 经典帧正常、FD 失败 | 两端都启用 FD，再核对仲裁段、数据段位率与每帧 BRS；见对应使用手册。 |

先保留 `list`/`ip link`、发送和接收三处实际输出，再继续定位问题。第一帧通过后，按[验收测试路线](验证路线.md)选择功能、矩阵、压力与内核专项；开发业务协议再看[DBC/CANopen 开发](CANopen与DBC开发指南.md)。无需先理解底层 USB 帧布局。
