# 验收测试路线

先按[快速入门](01_快速入门.md)确认设备模式、驱动、两路 CAN 接线与第一帧。写 Python 程序的用户可先运行[API 验证](06_API验证.md)，再做下述压力测试。测试会改变位时序、终端电阻和接口状态，只在隔离测试总线上运行。准备两个通道：CANH 接 CANH、CANL 接 CANL。

| 当前主机端路径 | 执行哪一项 | 完成标志 |
|---|---|---|
| Python 后端直接打开 USB | 本页“Python USB 完整验收” | `COMPLETE PYTHON USB SUITE PASSED` |
| Linux 驱动创建 `canX` | 本页“Linux SocketCAN 完整验收” | `COMPLETE SOCKETCAN STRESS TEST PASSED` |

两条路径测试的是不同软件层；同一 USB interface 不能同时被内核模块和 Python 后端占用。只运行与当前主机端路径对应的命令。退出码非零、缺少必要阶段或只显示部分阶段结果，都不能判为通过。

## 开始前保存身份与构建信息

SocketCAN 路线记录 `ethtool -i canX` 和 `/sys/class/net/canX/device_info/` 下的 UID、UUID、固件版本、硬件修订及原始硬件字段；Python 路线用 `canctl --interface <当前后端> --channel <接口号> info`。不要为了查询身份临时用 Python 抢占内核绑定。

同一板卡不同通道的 UID/UUID 应一致，通道号另行记录。查询不可用时记录错误及固件模式，不以 USB 序列号填充 UID/UUID。更新内核模块后，须确认实际加载了新版本再验收。

## Python USB 完整验收

在 `python-cli/` 目录，Windows PowerShell 执行：

```powershell
py canctl.py test --interface vcan_usb
```

GS_CAN 模式使用 `--interface vkgs_usb`。Linux 上先按[快速入门](01_快速入门.md)配置 udev 免 sudo 权限，并按 doctor 输出释放目标板卡的内核绑定，然后运行 `python3 canctl.py test --interface vcan_usb`。脚本只运行完整双通道测试，默认每个发送端、每阶段 10000 帧、窗口 32、重复打开 5 次；混合帧矩阵至少覆盖 100 种情况。它检查 250 kbit/s 与 1 Mbit/s 经典帧、经典/FD 混合、定向序号、双向总线、每路内部回环、FD/BRS、重复打开和 USB/CAN 错误计数。缺少 FD、双通道或任何阶段失败都会判失败。

延长压力测试只需提高帧数或轮数：

```powershell
py canctl.py test --interface vcan_usb --frames 20000 --rounds 3 --results-json results.json
```

`--frames` 表示**每个发送端、每个阶段**的帧数，最少 100；`--rounds` 重复整套测试。窗口控制一批尚未确认的序号，默认 32，可用 `--window` 调整以排查背压。每阶段核对 TX/RX 帧数和载荷字节数相同、invalid/duplicate/reorder 为 0、应用队列 overflow/drop 与 USB 错误为 0、CAN 状态为 ACTIVE。USB transfer 次数不是 CAN 帧数。只有所有阶段完成才显示 `COMPLETE PYTHON USB SUITE PASSED`。脚本异常时不重发结果不确定的 CAN 帧，并保留首个及少量后续异常样本。

## Linux SocketCAN 完整验收

首次加载或从 Python USB 切回时，先关闭 Python，再从仓库根目录运行 `sudo bash kernel/tests/vcan_usb/test_vcan_usb.sh --load-only`（GS_CAN 将目录和脚本名中的 `vcan_usb` 改为 `vkgs_usb`）。该选项只加载并检查绑定，不发 CAN 帧。`--no-build` 同时跳过编译和加载，仅适用于已有绑定；临时模块使用 `rmmod` 卸载。测试会操作绑定到该驱动的接口，请先停止相关业务。

此项使用 `kernel/` 的驱动，和 Python USB 测试分开。在仓库根目录执行与当前模式相应的一条命令：

```bash
sudo bash ./kernel/tests/vcan_usb/test_vcan_usb.sh
sudo bash ./kernel/tests/vkgs_usb/test_vkgs_usb.sh
```

默认在 `/tmp` 构建驱动；已加载同版本且两路接口已绑定时保留绑定，否则重载。同版本源码有修改时，这个判断不能保证加载了新实现，须先按[安装说明](08_Linux内核驱动安装.md#51-确认身份查询功能已加载)重载并确认身份查询功能。随后运行 250 kbit/s 混合帧、ECU 周期/事件/诊断流量、ISO-TP、J1939 TP、序号完整性、FD 往返、目标总线负载、1 Mbit/s 混合帧、FD 压力和重复打开。要求全部项目可用，缺少 FD 或必需工具会失败，不再有“部分覆盖通过”。

用 `--frames` 控制每个发送端的帧数，默认 10000，负载阶段也严格遵循指定数量；`--reopen-loops` 控制重复打开次数。普通压力阶段不加固定发送间隔，SocketCAN 队列满时等待可写后继续。ECU 周期场景保留按报文周期发送，但也在完成指定帧数后结束。例如：

```bash
sudo bash ./kernel/tests/vcan_usb/test_vcan_usb.sh --frames 20000
```

已经构建并加载当前驱动时可加 `--no-build`。内置 CAN-FD 往返工具保持最多 50 帧在途，每个方向精确发送 `--frames` 帧。ISO-TP 按 FF/CF 数据帧计数，J1939 按 TP.DT 数据帧计数，流控开销另外统计；`ISOTP_SIZE`、`J1939_SIZE` 为单消息载荷上限。无间隔负载依靠背压尽快发送，超时、丢帧、数据或控制器错误判失败，吞吐率仅作诊断。只有全部阶段完成才显示 `COMPLETE SOCKETCAN STRESS TEST PASSED`。

## 保存测试结果

保存设备模式、UUID 与通道号、固件版本、接线和终端配置、实际命令、测试退出码，以及报告中的帧数、错误和丢弃计数。只有完整运行并显示对应的 `COMPLETE ... PASSED` 才视为本项通过。失败时保留终端输出和已生成的结果文件，按[常见问题](02_常见问题.md)排查。
