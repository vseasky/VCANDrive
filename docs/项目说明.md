# VCANDrive 项目说明

## 项目定位

VCANDrive 是 HPMicro 双通道 USB-CAN FD 设备的主机端软件与开发资料仓库。目标是在不要求应用理解 USB 私有端点细节的前提下，提供两条清晰路径：

1. Linux 原生 SocketCAN：设备表现为 `canX` 网络接口，复用标准 Linux CAN 生态。
2. 跨平台 Python USB API：设备表现为 `python-can` backend，适合自动化、测试和工具开发。

仓库还提供命令行工具、mock 单元测试、硬件验收脚本，以及 CANopen/DBC 应用层开发资料。

## 组件边界

| 层级 | 仓库组件 | 负责内容 | 不负责内容 |
|---|---|---|---|
| 设备固件 | 不在本仓库；参考 `../03.FirmWare` | USB personality、CAN 控制器与硬件功能 | 主机应用业务逻辑 |
| Linux 驱动 | `kernel/vcan_usb`、`kernel/vkgs_usb` | USB ↔ SocketCAN netdevice、位时序、状态与终端 | DBC/CANopen 业务协议 |
| Python transport | `python-cli/vcan_usb`、`python-cli/vkgs_usb` | USB ↔ `can.BusABC`、发现、收发、生命周期 | SocketCAN netdevice |

| 应用协议 | 用户项目、项目 Skills 与开发指南 | DBC signal、CANopen、诊断/控制逻辑 | USB 驱动实现 |

## 两套 USB 协议

### VCAN 原生（`1d50:6080`）

- Linux module / Python interface：`vcan_usb`。
- 每帧含 opcode 长度前缀，接收聚合包可以按长度逐帧解析。
- 扩展控制请求包含设备信息、模式、位时序、终端、总线负载和 USB personality 切换。

### GS_USB / VKGS（`1d50:606f`）

- Linux module / Python interface：`vkgs_usb`。
- 兼容 candleLight / gs_usb 数据格式并包含项目扩展请求。
- Linux 主线 `gs_usb` 可能自动绑定该 VID:PID；本项目 `vkgs_usb` 处理固件无 TX echo、寄存器位时序和扩展请求。

### PEAK 兼容模式

设备固件可支持切换到 PEAK 兼容 personality，但本仓库不提供该模式的 Linux/Python 驱动。已有 PCAN 生态的环境应使用对应兼容驱动和工具链。

## 共同能力与约束

- 每个 CAN 通道对应一个独立 USB interface 和 bulk IN/OUT 端点。
- 端点由 USB descriptor 发现，不应在用户应用中写死。
- CAN controller 时钟为 80 MHz，驱动/backend 根据请求速率计算位时序。
- 支持 classic CAN、CAN FD、BRS、loopback、listen-only、one-shot、berr-reporting 和可切换 120 Ω 终端；最终能力仍以设备 feature 与驱动报告为准。
- 固件发送完成不返回普通 TX echo；驱动/backend 的回显与统计策略已针对该行为适配。
- 同一 USB interface 不能同时被内核驱动和 Python USB backend 占用。

## API 稳定面

Linux 应用应依赖标准 SocketCAN ABI：`PF_CAN`、`CAN_RAW`、`can_frame`、`canfd_frame` 与每 socket filters。除开发管理工具外，不应直接发 USB vendor request。

Python 应用应依赖 `python-can` 的 `BusABC` 接口和本项目明确列出的扩展方法。`protocol.py` 与 `transport.py` 属于 backend 内部实现，不建议业务项目直接导入。

设备模式切换、硬件 filter 和 OTA 类操作属于设备管理面；它们与普通 CAN 收发隔离，并需要更严格的目标选择和授权。

## 验证策略

- Python mock/unit：不访问硬件，验证 codec、backend 生命周期和错误转换。
- Linux `vcan`：验证 PF_CAN、filters、DBC 与上层状态机，不验证物理层。
- 单通道内部回环：验证控制器与 USB 数据路径，不验证外部总线 ACK/终端。
- 双通道共享总线：验证 classic CAN、FD/BRS-off、FD/BRS-on 与实际接线。
- 故障注入：仅在隔离网络验证无 ACK、BUS-OFF、断连与恢复。

硬件验收脚本会真实改动接口配置并产生总线流量，不应在生产网络运行。

## 非目标

- 不在此仓库发布 VCAN 固件镜像或硬件设计文件。
- 不把 DBC、CANopen、UDS 等应用协议硬编码进内核驱动。
- 不承诺 Linux `canX` 名字等于面板通道顺序。
- 不提供 PEAK personality 的替代驱动。
- 不保证不同进程能够共享同一个 USB interface；需要共享时由单进程负责 Bus 并向上层分发。
